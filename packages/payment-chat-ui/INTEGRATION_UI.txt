  cd packages/payment-chat-ui

개발 서버와 미리보기 서버는 같은 포트를 사용하므로 동시에 실행하지 않는다.
프로젝트별 패키지 저장소 설정이 다른 환경에서는 설치 후 npm run dev/build/preview로도 실행할 수 있다.
잠금 파일은 pnpm-lock.yaml 하나만 관리한다. esbuild 설치 스크립트만 로컬 설정에서 허용한다.

구현한 화면
- 무료 추천 3명 및 상세 프로필
- 선택한 상대에게 500원으로 대화 요청하는 결제 안내
- 결제 확인 중 / 확인 지연 / 완료 상태
- 받은 요청의 무료 수락 및 거절, 보낸 요청의 대기 상태
- 대화 목록, 일대일 채팅, 메시지 입력·송신·수신
- 모바일 하단 메뉴와 대화 목록/채팅방 전환
- native dialog를 이용한 키보드 포커스 제한, Escape 닫기, 입력 레이블, 상태 안내

체험 순서
1. 서연 프로필 보기 → 대화 시작 500원 → 500원 결제 체험하기.
2. 확인 완료 후 대화 요청 보내기 → 상대 수락 체험.
3. 메시지를 보내고 상대 답장 체험 버튼으로 수신 확인.
4. 같은 프로필을 다시 열면 대화 이어가기가 표시되며 새 결제를 하지 않는다.
5. 처음부터 도착해 있는 민준의 요청은 결제 없이 수락하거나 거절할 수 있다.
6. 다른 상대의 결제 안내에서 데모 시나리오 선택 → 확인 지연을 선택하면 같은 주문 재확인을 볼 수 있다.
   '같은 주문 다시 확인'은 조회만 한다. 별도 '지연된 데모 결제 완료하기'로 완료를 체험한다.
   '환불 대기'는 가상 상대를 비활성화해 결제 기록 보존/환불 대기 안내를 보여준다.
   '결제 취소'는 미결제 주문만 취소 상태로 바꾸며 두 상태 모두 대화 요청을 허용하지 않는다.
   환불 대기 체험 후 상대 상태를 되돌리려면 데모를 초기화한다.
7. 데스크톱 왼쪽 아래 새로고침 아이콘으로 데모 초기화. 모바일은 서버 재시작으로도 초기화 가능.
모든 결제 관련 버튼은 데모임을 표시하며 실제 결제창으로 이동하거나 청구하지 않는다.

실제 호출 흐름
React 화면 → 기존 createBrowserClient → 로컬 /api → 기존 createHttpApi → 기존 createService
→ demo/store.ts의 메모리 트랜잭션 저장소 → 응답 → 화면.
Node 서버에는 실제 C 서비스와 동일한 주문/상대별 권한/참여자 검사를 사용한다.
데모의 로그인 사용자는 demo-me로 고정되어 있으며 운영 인증으로 사용하면 안 된다.
결제 완료·상대 수락·상대 답장은 /api/demo/* 전용 동작이다.
이 경로와 모의 결제 검증기는 Vite의 로컬 개발/미리보기 플러그인에만 존재한다.
dist/는 정적 화면 빌드일 뿐 운영 API 서버가 아니다. 이 폴더만 배포하면 실제 서비스가 되지 않는다.
데모는 실시간 구독 대신 2.5초 간격 조회로 새 메시지를 확인한다.

A와 실제 앱에 연결할 때
1. 재사용 화면은 src/PaymentDialog.tsx, src/ChatPanel.tsx, src/ui.tsx 및 styles.css다.
   각 컴포넌트는 Next.js 클라이언트 경계를 선언했다. styles.css는 공통 레이아웃에서 한 번 불러온다.
2. src/App.tsx는 가상 추천 데이터와 데모 제어가 들어 있는 검토용 조합 예시다.
   src/catalog.ts의 인물, src/demo-client.ts 및 demo/ 전체를 운영 코드에 포함하지 않는다.
3. A의 인증과 B의 무료 추천 결과를 화면 props로 전달한다.
   실제 사용자 ID는 Supabase Auth UUID를 사용하며 MY_ID 상수는 제거한다.
4. 기존 C 서버 모듈에 실제 Groble 및 Supabase 어댑터를 연결하고, 공통 앱의 /api 라우트로 탑재한다.
5. PaymentDialog의 onConfirm은 실제 결제창 이동으로 교체한다.
   복귀 화면은 저장한 주문 ID로 createCheckoutFlow.resume()를 호출한다.
6. ChatPanel의 demo props를 생략하면 체험 버튼/안내가 나타나지 않는다. PaymentDialog는 paymentAction.kind=checkout으로 전달한다.
   상대방의 실제 수락과 메시지를 Supabase Realtime으로 전달한다.
7. 메시지의 snake_case DB 필드를 ChatMessage의 camelCase로 변환한다.
   메시지 전송 응답과 실시간 이벤트는 기존 createMessageTimeline으로 합쳐 중복 표시를 방지한다.
8. 공통 React 버전과 의존성을 통일하여 React가 중복 로드되지 않도록 한다.
   독립 미리보기용 Vite 설정과 잠금 파일은 공통 앱 통합 시 별도로 정리한다.
9. 구매 전 가격·상품 범위·상대 수락을 보장하지 않는다는 설명을 유지한다.
   같은 상대와의 대화 재개 및 받은 요청의 수락·답장은 재결제를 요구하지 않는다.
