팀 결정이 필요한 결제·채팅 정책
상태: 미정. 현재 동작을 정식 정책으로 승인한 문서가 아니다.

D01. 상대방이 대화 요청을 거절하면 환불할까?
현재 구현:
- 요청은 rejected로 남고 이전 요청에서 다시 볼 수 있다.
- 같은 방향의 요청을 반복 생성하지 않는다.
- 거절 동작은 주문을 환불 상태로 바꾸거나 Groble 환불을 호출하지 않는다.
선택할 것:
- 자동 환불 없음 / 거절 시 환불 요청 / 별도 검토 절차 중 팀이 결정한다.
- 환불을 선택하면 요청 거절과 결제 확인의 순서, 환불 재시도·중복 웹훅, 실패 안내를 함께 정한다.
확인 담당: 팀 기획 결정 + C 구현 범위 + Groble 환불 규격.
확정 정책/확정자/적용일: __________
검증해야 할 것: 같은 주문에 환불 요청 1회, 수락과의 경합, 실패 시 상태 보존.

D02. 환불 후 이미 열린 채팅방을 유지할까?
현재 구현:
- 채팅 조회·전송은 방 참여자와 양방향 차단을 확인한다.
- 주문의 refunded 상태와 기존 방 접근을 연결해 차단하는 규칙은 없다.
- 실제 Groble 환불 어댑터는 아직 연결되지 않았다.
선택할 것:
- 기존 방 유지 / 읽기만 허용 / 새 메시지·기록 접근 종료 중 팀이 결정한다.
- 기존 메시지 보존과 사용자 열람 권한을 별도로 정한다. 환불만으로 기록을 임의 삭제하지 않는다.
- 같은 두 사람의 다른 주문·기존 무료 방이 있을 때의 적용 단위도 정한다.
확인 담당: 팀 기획 결정 + B 권한/RLS + C API·Realtime 처리.
확정 정책/확정자/적용일: __________
검증해야 할 것: 양쪽 계정·HTTP·RLS·Realtime에서 같은 결과, 다른 정상 방에 영향 없음.

이번 준비 작업에서는 위 정책과 가격·권한·DB 데이터를 변경하지 않는다.
