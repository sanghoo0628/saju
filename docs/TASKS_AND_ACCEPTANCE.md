# 개발 작업과 완료 기준

> **2026-11-16 최신 기준:** 이번 작업은 **A 범위만** 구현한다. 추천 3명 열람은 무료이며 선택한 상대당 500원은 대화 요청 권한에 적용한다. 기존 대화 재결제 없음, 수신자 수락·답장 무료. 아래의 유료 프로필 공개·주문당 3명 제공 관련 체크와 수용 테스트는 이전 기준이다. [변경 결정](DECISIONS.md), [최신 통합 수용 기준](TEAM_CONTRACT.md), [실제 구현 상태](STATUS.md)가 우선한다. 원래 체크리스트는 배경 자료로 보존한다.

현재 상품 범위와 데이터 계약은 CODEX_HANDOFF.md가 우선한다. 아래 항목은 구현 순서이며, 완료 표시는 실제 검증 후에만 한다.

- [ ] 결정 기록 파일 생성: 제안과 확정, 변경 이유, 담당자, 버전.

## 5. 결제와 추천 공개 — C+B

- [ ] 후보 3명 이상일 때만 서버 고정 500원 주문 생성.
- [ ] 주문 생성 재시도 멱등 처리, 주문별 무작위 ref.
- [ ] Groble 실제 payload 스키마 기반 검증.
- [ ] raw body HMAC·timestamp·상품·금액·주문·거래 검증.
- [ ] 로그인 proxy 제외, 공개 HTTPS 웹훅 수신.
- [ ] 이벤트 저장·주문 잠금·거래/이벤트 중복 제약.
- [ ] DB 트랜잭션으로 3명과 fulfilled 상태 확정.
- [ ] paid이지만 제공 실패한 상태와 복구/환불 필요 처리.
- [ ] 취소 요청/환불 완료·역순 이벤트 구분.
- [ ] 복귀 페이지 주문 소유권·다중 탭·조회 대기 처리.
- [ ] 새로고침 시 기존 3명 유지, 권한 우회 차단.

완료: 한 결제로 한 주문의 결과가 정확히 한 번 제공되고, 실패 시 돈과 권한 상태가 일치한다.

## 7. 필수 수용 테스트

| ID | 조건 | 기대 결과 |
|---|---|---|
| AUTH-01 | 미인증 주문 생성 | 401, 주문 생성 안 됨 |
| AUTH-02 | 클라이언트가 다른 buyer_id 전송 | 해당 ID로 주문 생성 불가 |
| AUTH-03 | 학교 미확인·프로필 미완 | 정책에 맞는 오류, 결제 차단 |
| MATCH-01 | 같은 입력·버전 반복 | 같은 점수와 동점 순서 |
| MATCH-02 | 후보가 2명 | 결제 시작 불가 |
| MATCH-03 | 차단/비공개/탈퇴 후보 | 노출 제외 |
| MATCH-04 | hybrid 승인 규칙 누락 | not_ready, 임의 점수 없음 |
| MATCH-05 | 생시 미상·일부 파생지표 누락 | 공통 기준 유지, 목록 내 모델 혼합 없음 |
| MATCH-06 | 같은 evidence가 여러 설명에 등장 | 점수는 한 번만 반영 |
| PAY-01 | 동일 웹훅 병렬·반복 전달 | 결과 정확히 3개, 중복 지급 없음 |
| PAY-02 | 다른 이벤트 키지만 같은 거래 | 추가 제공 없음 |
| PAY-03 | 서명/시간/상품/금액 불일치 | 결제 권한 부여 안 됨 |
| PAY-04 | 결제 복귀가 웹훅보다 빠름 | 확인 중 → 올바른 상태로 갱신 |
| PAY-05 | 복귀 페이지 직접 방문·타인 주문 | 프로필 공개 안 됨 |
| PAY-06 | 동시에 여러 결제 탭 | 주문 혼동 없음 |
| PAY-07 | 결제 중 후보가 소실 | 재선정 3명 또는 paid+refund_required |
| PAY-08 | 환불→완료 순서로 이벤트 도착 | 환불 후 권한 복원 안 됨 |
| PAY-09 | DB 커밋 실패 | 거짓 성공 응답 없음, 재처리 가능 |
| PAY-10 | 결과 새로고침·전략 변경 | 구매 당시 동일한 3명 유지 |
| CHAT-01 | 요청자가 수락 시도 | 거부 |
| CHAT-02 | 수신자 미결제 상태로 수락 | 정상 수락 |
| CHAT-03 | 양방향 동시 수락 | 동일 방 1개 |
| CHAT-04 | 제3자 조회·구독·sender 위조 | 전부 차단 |
| CHAT-05 | 차단 후 새 메시지 | DB에서 거부 |
| CHAT-06 | 연결 끊김 후 재접속·전송 재시도 | 누락 복원, 중복 없음 |
| DATA-01 | 사진 URL·직접 DB 접근 | 유료/참여자 권한 우회 불가 |
| ENV-01 | 운영에 mock 결제 플래그 | 활성화 거부 |
| BOOK-01 | 외부 링크 클릭만 발생 | confirmed/commission 확정 안 됨 |
| BOOK-02 | 상대가 활동 제안 미동의 | 예약 실행 안 됨 |
| BOOK-03 | 재고 소진/중복 요청/환불 | 명시적 상태, 중복 예약·수익 없음 |

보안·결제·동시성 테스트를 단순 화면 테스트로 대체하지 않는다. RLS는 관리자 키가 아닌 실제 사용자 토큰으로 검사한다. 필요한 검사를 통과하면 불필요하게 동일 검사를 반복하지 않는다.
