C API 응답 지연 복구
2026-11-23 / codex/c-payment-chat

문제
C 브라우저 API에는 요청별 제한 시간이 없었다.
fetch 또는 response.json이 끝나지 않으면 메시지 전송·주문 생성·수락/거절 UI가 계속 대기할 수 있었다.
기존 메시지 재전송 추적은 요청이 실패해 돌아온 뒤 동작하므로 무한 대기에는 복구 버튼이 나오지 않았다.

구현
packages/payment-chat/src/client.ts의 모든 C API 호출에 기본 15초 제한을 적용했다.
시간은 응답 헤더 수신과 JSON 본문 읽기를 모두 포함한다.
제한 시간에는 내부 AbortController를 취소하고 REQUEST_TIMEOUT/408 클라이언트 오류로 종료한다.
전송 계층이 abort를 무시하더라도 호출은 Promise.race로 종료하며 늦은 응답은 화면 결과로 전달하지 않는다.
이 오류는 API의 서버 오류 코드 계약을 바꾸지 않는 브라우저 전용 오류다.
브라우저 타이머는 백그라운드 탭·절전 상태에서 지연될 수 있다.

호환성과 동작
createBrowserClient(fetcher?, { timeoutMs?, schedule? }?) 형식으로 두 번째 선택 설정만 추가했다.
기존 호출 및 fetch 주입, 개별 API 인자·쿠키·same-origin·no-store 정책은 유지한다.
사용자가 방을 나가거나 로그인 상태가 바뀌어 전달한 AbortSignal이 취소되면 해당 취소 사유를 보존한다.
완료/오류/취소 시 타이머와 부모 신호 리스너를 정리한다. 동시 요청은 각각 독립된 제한 시간을 갖는다.
기본값은 15000ms이며 설정 범위는 정수 1~120000ms다.

POST는 자동 재시도하지 않는다.
시간 초과는 서버에서 주문·수락·메시지가 처리되지 않았다는 뜻이 아니다.
주문/요청은 기존 서버 상태를 확인하고, 메시지는 기존 UUID와 본문으로 사용자가 명시적으로 재전송한다.
조회는 기존 화면 세션의 polling/checkout resume 정책을 그대로 따른다.
기존 인증/차단 거절과 잘못된 JSON·네트워크 오류는 원래 코드와 의미를 유지한다.
UI·DB 스키마·마이그레이션·가격·인증 정책은 변경하지 않았다.

검증한 사용자 흐름
채팅 입력 → POST → 데모 저장 완료 → 응답을 끝내지 않음 → 15초 뒤 전송 대기 해제 →
본문 보존 및 재확인/재전송 버튼 표시 → 새 초안 작성 → 이전 메시지 재전송 →
원본 메시지 한 개 표시, 새 초안 유지.
공유 Supabase 대신 별도 메모리 데모와 로컬 장애 프록시를 사용했다.
관측값: messagePosts=2, uniqueIds=1, firstTwoSameId=true,
upstreamMessageCount=1, timedOutConnections=1.
첫 timeout 뒤 자동으로 두 번째 POST가 나가지 않는 것도 확인했다.

회귀 검사
추가 검사 14개: 헤더 무응답, JSON 읽기 무응답, 호출자 취소, 리스너/타이머 정리,
오류 의미 보존, 병렬 요청 독립성, 설정 검증, 5종 POST 자동 재시도 금지,
HTTP 어댑터/서비스/메모리 저장소를 거치는 저장 후 timeout 재전송,
주문 대기 해제 후 명시적 재시도.
전체 기본 검사: B/DB 114 + C 161 + A 97 + UI 18 = 390개 통과.
ESLint, 타입 검사, Next build, Vite build, 로컬 HTTP 20개 통과.
최초 로컬 실행에서는 loopback 권한 제한으로 DB wire/HTTP 검사가 실패했다.
네트워크 권한을 승인받은 후 같은 검사를 다시 실행해 모두 통과했다.
네이티브 PostgreSQL은 로컬 IPC 제한이 남아 있어 기존 12개를 GitHub Linux CI에서 확인한다.
최종 CI 결과
코드 커밋: a5595e50547f65cfded659208cade06dc64e201b
GitHub Actions: https://github.com/sanghoo0628/saju/actions/runs/45128134156
전체 conclusion=success. App, API and UI / Native PostgreSQL concurrency 모두 성공.
기본 390개 + native PostgreSQL 12개 = 자동 테스트 402개 통과. HTTP 20개도 통과.
ESLint, 타입 검사, Next/Vite 빌드 모두 통과. native 종료 오류도 없었다.
이 기록만 추가하는 후속 문서 커밋은 CI paths-ignore 규칙에 따라 다시 실행하지 않는다.
이번에 띄운 로컬 장애 프록시와 데모 서버는 종료했다.

격리 범위와 다음 작업
이번 작업에서 공유 Supabase 데이터·스키마와 실제 결제는 변경/실행하지 않았다.
.env.local과 실제 키는 Git에 포함하지 않는다. 추가 의존성은 없다.
main과 A/B 브랜치는 수정하지 않는다.
A/B 사주 저장 연동, 실제 학교 메일 수신, Groble 공식 결제/웹훅/환불은 기존 대기 항목이다.
