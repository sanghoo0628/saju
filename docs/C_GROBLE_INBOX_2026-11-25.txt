구현
- private.groble_events: 개인정보를 포함하지 않는 이벤트 메타데이터, 정규화된 업무 내용 해시,
  pending_mapping / applied / review_required 처리 상태와 연결 주문.
- private.groble_deliveries: 전송 멱등 키를 이벤트 ID에 연결. 다른 이벤트에 키 재사용 시 거부.
- private.groble_refunds: 원 거래+환불 완료 시각 기준 중복 집계 방지, 부분 환불 누적.
- 세 테이블은 private 스키마, RLS, anon/authenticated 권한 회수, service_role만 필요한 권한 부여.
- createGrobleInbox.receive: 서명 검증기 통과 후 같은 SQL 연결의 SERIALIZABLE 트랜잭션 안에서
  이벤트·전송·결제 기록·주문 상태를 반영. SQL 실패 시 전체 롤백.
- 같은 거래의 생애주기 작업을 advisory lock으로 직렬화. 충돌은 제한된 재시도로 재조회.
- 기존 결제 완료 규칙은 applyCompletedPayment로 추출하여 기존 서비스와 공유.
- 환불이 먼저 오면 pending_mapping으로 영속 보관. 완료 이벤트가 나중에 원 주문을 연결하면
  누적 환불까지 함께 반영하므로 환불된 권한을 늦은 완료 이벤트로 되살리지 않음.
- 취소 요청만으로 접근 권한을 바꾸지 않음.
- 부분 환불액이 500원 미만이면 review_required, 기존 권한 유지. 부분 환불 정책은 팀 합의 필요.
- 누적 환불액이 주문 금액 이상이면 refunded. 500원 초과 기록은 review_required도 남겨 검토.
- 환불 후 새 대화 요청·미수락 요청 수락은 기존 서비스의 주문 검사로 거부.
- 이미 수락한 방은 기존 서비스 정책대로 유지. 정책 변경을 새로 도입한 것은 아님.
