확인한 문제
- 기존 이름·학과 조회는 상대 ID 목록이 바뀔 때만 실행됐다.
- 같은 상대 목록에서 첫 조회가 실패하면 이름이 계속 '알 수 없는 사용자'로 남을 수 있었고, 별도 재시도 UI가 없었다.
- SDK 조회에 전체 시간 제한이 없고, 큰 목록에서 모든 배치를 동시에 시작했다.

수정
- Browser Supabase RLS 클라이언트로 id/nickname/major만 조회한다. 관리자 클라이언트·비밀 키·새 API·SQL은 추가하지 않음.
- 전체 조회15초 제한. SDK에 AbortSignal 전달, 취소를 무시하는 조회도 UI 대기를 종료.
- 50명씩 최대4개 동시 조회. ID 중복 제거, 부분 성공 유지.
- 실패/시간 초과 시 '상대 정보 다시 불러오기' 제공. 메시지 전송·수락·참여 권한을 프로필 정보 성공 여부에 연결하지 않음.
- 화면 이동/상대 목록 변경 시 취소. 늦은 결과는 게시하지 않음. 화면에는 현재 ID 목록·재시도 키와 맞는 정보만 표시.
- RLS로 숨겨지거나 삭제된 프로필의 빈 응답은 정상으로 취급. 외부 ID/잘못된 행은 노출하지 않고 실패 표시.
- 오류 객체·생년월일·이메일 등은 반환/로깅하지 않고 필요한 공개 필드만 복사.
- 프로필 권한이나 차단 정책을 바꾸지 않고 기존 서버 검증을 유지.
