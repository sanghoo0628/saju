C Groble HTTP 수신부 준비 — 2026-11-25 KST

브랜치: feature/c-groble-event-verification
기존 영속 이벤트/SQL 트랜잭션 코드에 HTTP 수신 팩터리를 추가함.
main / 실제 배포 / saju-dev / 결제 활성화 설정은 변경하지 않음.

동작
- src/server/groble-webhook-handler.ts: createGrobleWebhookHandler({receive,onUnexpectedError})
- 정확한 /api/webhooks/groble 경로, POST, application/json만 수신.
- 로그인 쿠키/학교 사용자/브라우저 Origin에 의존하지 않음. 인증은 주입한 수신부의 원문 서명 검증.
- 256KiB 제한을 실제 스트림에도 적용. 허위 Content-Length로 제한을 우회할 수 없음.
- 본문 수신에 기본 5초 제한. 업로드 정지/초과 시 스트림을 취소하고 저장 호출하지 않음.
- 원문 바이트와 헤더를 재직렬화 없이 inbox.receive로 전달.
- receive가 DB COMMIT 후 resolve해야만 응답. 백그라운드 처리 예약을 성공으로 간주하지 않음.
- applied=200, 영속 저장된 pending_mapping/review_required=202.
- 잘못된 서명/주문 입력=400, 본문 초과=413, 형식 오류=415, 본문 시간 초과=408.
- DB 장애/롤백/예상하지 못한 실패=503 + Retry-After:5.
- 응답에는 내부 주문/이벤트 식별자, 원문, 오류 메시지, 키를 포함하지 않음.
- 오류 로거는 기존 logPaymentChatError('request', error)로 연결해야 함. 원문 로깅 금지.

연결 방법 (아직 실행하지 않은 서버 코드 예시)
const verify = createGrobleEventVerifier({ productId, secret, previousSecret, previousSecretExpiresAt });
const inbox = createGrobleInbox({ pool, verify });
const handler = createGrobleWebhookHandler({
  receive: inbox.receive,
  onUnexpectedError: error => logPaymentChatError('request', error),
});

남은 실제 연결 조건
1. B가 새 마이그레이션 20261125000100을 검토·적용했는지 확인.
2. Groble 상품/판매자/웹훅 시크릿 및 등록 URL 확인. 키는 채팅이나 Git에 저장하지 않음.
3. 기존 Next route와 payment-chat-runtime이 위 handler를 호출하도록 별도 연결.
   현재는 unavailablePaymentGateway 그대로이며 새 handler가 배포 경로를 대체하지 않음.
4. 전체 10초 응답 예산을 위한 연결/쿼리/재시도/플랫폼 타임아웃 검증 필요.
   본문 5초 제한만으로 DB 작업 전체의 10초 제한을 보장하지는 않음.
   DB 처리 중 Promise.race로 성공/실패를 먼저 응답하거나 무제한 백그라운드 작업으로 넘기지 않음.
5. 실제 서명 테스트 발송으로 이벤트 저장·재전송·역순 처리와 2xx/실패 응답 검증.
6. 실제 결제/환불 테스트 및 부분 환불/기존 대화 정책 합의 후 활성화.

  원문 보존, 멈춘 업로드 취소, 실제 HMAC 검증기를 통한 인증 경계.
