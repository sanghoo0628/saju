C 이전 대화 요청 조회
2026-11-23 / codex/c-payment-chat

문제와 변경
기존 목록은 pending 요청만 보여줬다. 거절 결과를 본 뒤 목록을 나가거나 새로고침하면 다시 선택할 방법이 없었다.
API가 이미 반환하는 accepted/rejected 요청을 이전 대화 요청 영역에 표시하도록 했다.
기본은 접힌 details/summary이며 사용자가 열어 지난 결과를 확인한다.
받은 요청/보낸 요청과 수락됨/거절함/거절됨을 구분한다.
수락된 이력과 동일 상대의 기존 방이 있으면 바로 해당 방을 연다(추가 결제 없음).
방이 아직 조회되지 않으면 기존 수락 결과 화면과 대화방 다시 확인 동작을 사용한다.
거절된 이력은 결과 조회만 제공한다. 재요청·재결제·자동 환불 정책은 추가하지 않았다.

구현 범위
packages/payment-chat-ui/src/ChatPanel.tsx와 styles.css를 변경했다.
현재 로그인 사용자의 요청만 추리는 기존 필터를 적용한 후 이력을 만든다.
서버/RLS가 조회를 허용한 목록만 사용하며 새로운 관리자 조회는 없다.
기존 GET 요청 목록/방 목록 API와 선택 콜백을 사용하므로 새 props/API/SQL은 없다.
목록의 기존 페이지 상한과 listHasMore 안내도 유지한다.
새 의존성, 결제 금액/권한, 인증, DB 마이그레이션은 변경하지 않았다.

검증
화면 회귀 검사 6개 추가:
- 보낸 요청의 거절 결과를 상세 선택 없이도 목록에서 발견할 수 있음
- 받은 요청 거절 이력에 수락/결제 동작이 없음
- 수락 이력과 기존 방이 있으면 무료 이어가기 안내
- 기존 방을 찾지 못했을 때 이어가기 가능하다고 잘못 표시하지 않음
- 다른 계정의 완료 요청은 숨김
- pending 요청이 이력에 중복 표시되지 않음
전체 기본 396개 = B/DB 114 + C 161 + A 97 + UI 24 모두 통과.
ESLint, 타입 검사, Next 빌드, Vite 빌드, 로컬 HTTP 20개 통과.

브라우저 시나리오
기존 4174 데모 대신 별도 4195 데모/4196 프록시를 사용했다.
1. 민준 가상 요청 거절 후 이전 대화 요청 1에서 받은 요청·거절함 표시 확인.
2. 이력을 다시 눌러 내가 거절한 요청 결과를 다시 확인.
3. 별도 가상 상대의 데모 결제·요청·수락을 준비한 뒤 페이지 새로고침.
4. 이전 대화 요청 2에 보낸 요청·수락됨과 받은 요청·거절함이 함께 표시됨.
5. 수락 이력의 무료 이어가기를 눌러 해당 상대의 실제 데모 채팅 입력창으로 즉시 이동.
장애 프록시의 주문 생성 POST 횟수는 준비 단계의 1회에서 늘지 않았다.
실제 사용자/결제/공유 Supabase 데이터는 사용하거나 변경하지 않았다.
브라우저 생성 도구가 오래 지연됐지만 응답 후 나머지 시나리오는 정상 확인했다.
