C PostgreSQL 트랜잭션 어댑터
2026-11-17 / codex/c-payment-chat

구현한 범위
- src/server/postgres-repository.ts: pg.Pool 연결, SERIALIZABLE 트랜잭션, 제한된 재시도, 연결 반환/폐기.
- src/server/postgres-transaction.ts: C ports.ts의 모든 메서드를 B 테이블/함수에 연결.
- BEGIN부터 COMMIT/ROLLBACK까지 같은 PoolClient만 사용한다. pool.query로 트랜잭션을 분산하지 않는다.
- 트랜잭션별 SET LOCAL ROLE service_role 및 statement_timeout/lock_timeout/idle timeout을 적용한다.
  기본값: 재시도 5회(최초 포함 최대 6번), statement/idle 15초, lock 5초, 풀 크기 10.
- 40001(직렬화 실패), 40P01(교착), 명시한 주문/결제/요청/방 고유 제약의 23505만 재시도한다.
  참조값 충돌 등 임의의 UNIQUE 오류, 비즈니스 오류, 결과가 불명확한 연결/COMMIT 오류는 재실행하지 않는다.
- 재시도 전 ROLLBACK하고 연결을 풀에 반환한다. 롤백 실패 연결은 폐기한다.
- 콜백이 SQL 예외를 삼켜도 성공으로 확정하지 않는다. 종료된 Transaction 객체는 재사용할 수 없다.
- SQL 입력은 파라미터로 전달한다. 커서는 해당 사용자/방 소속을 검사하고 최대 100개를 반환한다.
- 커서 비교는 DB 원본 timestamptz로 수행한다. JS Date의 밀리초 절삭으로 메시지를 건너뛰지 않는다.
- 계정 하드 삭제로 orders.buyer_id/target_id/match_result_id가 NULL이 될 수 있는 B 스키마를 반영했다.
  결제는 기록하되 buyer/target이 없어졌으면 refund_pending이다. OrderResponse.targetId는 string | null이다.
  실제 환불 API를 호출하는 기능은 아직 아니다.

A가 연결할 예시 (서버 모듈에서 한 번 생성)

  import { createPaymentChatDatabase } from '@/server/postgres-repository';
  import { createService } from '<C service.ts의 실제 프로젝트 경로>';

  const database = createPaymentChatDatabase(process.env.DATABASE_URL ?? '');
  const service = createService({ repository: database.repository, gateway: grobleGateway });

- grobleGateway는 실제 서명 검증을 구현한 결제 어댑터다. 테스트 검증기를 사용하면 안 된다.
- HTTP 어댑터에는 A의 getCurrentUserId()를 연결한다. 요청 본문의 사용자 ID를 신뢰하지 않는다.
- Next.js Route Handler는 Node.js 런타임을 사용한다. 이 모듈을 브라우저 컴포넌트에 import하지 않는다.
- 풀/서비스는 프로세스 단위로 재사용한다. 개발 HMR에서도 중복 생성하지 않게 서버 모듈에서 캐시한다.
- database.close()는 서버 종료/테스트 정리 때 사용하며 요청마다 호출하지 않는다.
- B 마이그레이션 6개가 적용된 DB가 필요하다. 이 팩토리는 마이그레이션을 자동 적용하지 않는다.
- DATABASE_URL은 서버 전용 DB 접속 문자열이다. Supabase HTTP URL/API 키와는 다르다.
- 로그인 DB 역할은 service_role로 SET ROLE할 권한이 있어야 한다. 브라우저/사용자에게 이 접속 정보를 주지 않는다.
- TLS는 제공자의 검증 가능한 연결 문자열/CA를 사용한다. 인증서 검증을 끄는 설정은 넣지 않았다.
- Supabase 트랜잭션 풀러를 쓸 때도 한 트랜잭션 동안 같은 클라이언트를 유지한다.
  이 어댑터는 연결 간 세션 상태나 이름 있는 prepared statement에 의존하지 않는다.
- 재시도 콜백 안에서는 모든 DB 호출을 await한다. 메일, 결제/환불 API 등 외부 부수효과를 넣지 않는다.
  결제 원문/서명 검증은 기존 service.ts대로 DB 트랜잭션 밖에서 실행한다.

실행해서 통과한 검증

  - C Node 테스트 61개
  - 합계 165개 통과
  npm run typecheck: 통과
  npm run demo:build: 통과

pg TCP 통합은 실제 pg.Pool/프로토콜과 B SQL/C 서비스가 왕복하는 검증이다.
대상 서버는 PGlite(WASM PostgreSQL)이며 단일 연결로 실행한다.
여러 네이티브 PostgreSQL 백엔드의 실제 동시성 검증을 대신하지 않는다.

별도 네이티브 PostgreSQL 검사 (추가 검증 필요)
  npm ci
  npm run test:postgres

- embedded-postgres로 로컬 PostgreSQL 18.6을 임시 디렉터리/임의 포트에 생성한다.
- 루프백 주소에만 바인딩하며 운영 DATABASE_URL이나 실제 Supabase에 연결하지 않는다.
- 사용자 계정 생성/전역 PostgreSQL 설치는 수행하지 않는다. 일반 사용자 권한으로 실행한다.
- B 마이그레이션 적용 후 다중 연결, 12개 동시 주문/웹훅, 요청/수락 경쟁, 양방향 수락,
  결제 롤백, 거래 ID 경합, 삭제 계정, 메시지 커서, 차단을 검사하는 테스트 10개를 준비했다.
- 기본 test:all과 별도 명령이다. test:all이 이 10개까지 통과했다는 의미는 아니다.
- 현재 Codex 실행 환경에서는 initdb의 shmget(shared memory)이 Operation not permitted로 차단됐다.
  서버 초기화 실패로 이 10개는 실행되지 않았다. 제한 없는 팀원 PC/CI에서 추가 실행해야 한다.
- npm이 네이티브 패키지 postinstall을 생략해도 테스트 설정 autoRehydrateSymlinks가 누락된 링크를 복원한다.
- 테스트 종료 시 연결 풀/서버를 닫고 자신이 만든 임시 DB 디렉터리를 제거한다.

남은 연결
A 공통 Next.js/Auth, 실제 Supabase 환경/TLS/역할 권한, Groble 서명/웹훅/환불,
Realtime 구독은 아직 실제 서비스에 연결하거나 검증하지 않았다.
main과 B 브랜치에는 변경하지 않는다. 배포하거나 외부 DB를 변경하지 않는다.
