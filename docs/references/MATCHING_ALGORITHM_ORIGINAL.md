# 대학생 사주 기반 소개·활동 추천 알고리즘 초안 v0.1

작성 기준: 2026-11-16
목적: 외부 API의 상세 사주 데이터를 받아 자체 기준으로 소개 후보를 정렬하고, 두 사람이 실제로 참여할 수 있는 활동을 연결한다.

이 문서는 개발 명세 초안이다. 모든 비중·임계값·예시 점수는 검증 전의 제품 정책이며, 명리학의 보편 공식이나 연애 성공확률이 아니다. 개인별 사주 계산은 외부 API에 맡기고, 매칭 정책·순위·설명·활동 연결은 자체 구현한다. 실제 API 연동이나 이용자 실험을 완료한 문서는 아니다.

## 1. 기본 설계

추천은 네 단계로 나눈다.

1. 상호 필수 조건을 만족하는 후보를 추린다.
2. 동일한 기준으로 계산한 사주를 비교한다.
3. 양방향 선호와 실제 만남 가능성을 결합해 순위를 정한다.
4. 근거를 설명하고 활동 선택지를 제안한다.

초기에는 다음 세 값을 모두 0~100으로 정의한다.

- S: 사주 해석 규칙 점수
- P: 양방향 자기 보고 선호 적합도
- M: 일정·이동·활동의 실행 가능성

최종 정렬 점수:

R(A, B) = 0.60 × S(A, B) + 0.25 × P(A, B) + 0.15 × M(A, B)

사주 중심 서비스라는 의도를 반영한 초기 비중이다. 같은 0~100 범위여도 각 값의 분포와 의미가 같지는 않으므로, 실제 데이터에서 분포를 확인하고 비중을 조정한다. R은 내부 순위 지표이며 사용자에게 성공률로 표시하지 않는다.

## 2. 받아야 할 데이터

### 2.1 외부 사주 API

HRUM 공식 문서의 필드명을 예로 들었다. 공급자 확정 후 어댑터에서 내부 코드로 정규화한다.

| 데이터 | 필드 예시 | v0 사용 |
|---|---|---|
| 년·월·일·시의 천간·지지 | wonkuk | 기본 원천 데이터 |
| 오행 분포 | ohaengBalance | 동일 기준의 분포 비교 |
| 용신과 해석 근거 | yongshinDetail | 조건부 해석 자료 |
| 신강약 | strength | 용신 해석의 문맥 |
| 십성 | 각 주의 stemSipsin 등 | 관계 설명, 별도 중복 가점 없음 |
| 원국 내부 관계 | branchRelations | 개인 설명, 쌍별 궁합으로 재사용 금지 |
| 대운·세운·신살 | daeun, seun 등 | 기본 추천 순위에서 제외 |
| 입력·옵션·버전 | 공급자 메타데이터와 자체 요청 기록 | 재현성·캐시·오류 추적 |

개인 원국 내부 관계와 A·B 사이의 관계는 별개다. 개인 응답의 branchRelations를 그대로 두 사람의 궁합으로 사용하지 않는다. 공급자의 종합 궁합 점수와 자체 세부 점수를 함께 더하지 않는다.

참고 문서:
- https://hrum.ai/manseryeok-api.html
- https://hrum.ai/docs.html

### 2.2 자기 보고 정보

- 필수 조건: 성인 여부, 소개 참여 동의, 필요한 학생 인증, 희망 나이·만남 대상·관계 목적, 생활권, 차단·제외 조건.
- 선택적 선호: 연락 빈도, 만남 빈도, 계획적인 약속 선호, 활동 분위기. 각 항목에 자신의 상태와 원하는 상대의 허용 범위를 별도로 입력한다.
- 실행 정보: 앞으로 14일의 가능한 시간, 허용 이동시간, 1인당 총예산, 관심 활동·피하고 싶은 활동.
- 활동 예약의 총예산은 매칭비와 필수 활동비를 포함한다. 제휴 수수료는 추천 적합도에 넣지 않는다.

사주에서 추정한 성격을 실제 자기 보고 답변으로 저장하지 않는다.

### 2.3 내부 저장 계층

- raw_chart: 외부 원천 응답
- provider_analysis: 공급자 해석 지표와 계산 기준
- pair_features: 자체 계산한 A·B 관계
- score_components: S·P·M과 하위 점수
- evidence: 점수에 반영한 근거와 항목
- limitations: 생시 미상, 사용할 수 없는 필드
- versions: 공급자·응답 스키마·규칙표·가중치 버전
- plans: 두 사람이 선택할 수 있는 활동 후보

API 키는 서버에서 관리한다. 상대에게 원본 생년월일시를 공개하지 않는다. 출생정보는 이름·연락처와 분리하고, 외부 전송·저장·삭제 범위를 제품 정책에 반영한다.

## 3. 후보 필터

다음 조건 중 하나라도 충족하지 못하면 점수로 보상하지 않고 소개 후보에서 제외한다.

- 성인·소개 동의·필요 인증이 충족되지 않음
- A의 필수 조건을 B가 만족하지 않거나, B의 필수 조건을 A가 만족하지 않음
- 차단·신고 처리·중복 소개 제외 대상
- 휴면 또는 소개 일시 중지 상태
- 공통 3주 계산에 필요한 원천 데이터가 유효하지 않음

두 모드를 구분한다.

- 상대 탐색 모드: 일정이 아직 없으면 ‘일정 미확인’ 후보로 구분한다. 일정 정보가 있는 후보와 같은 R 점수로 비교하지 않는다.
- 약속 제안 모드: 실제 공통 시간과 예산·이동 조건을 만족하는 활동이 없으면 ‘현재 약속 제안 불가’로 처리한다.

초기 주력은 약속 제안 모드로 설정한다.

## 4. 사주 점수 S

### 4.1 점수 카테고리

S = 0.30 × C_stem + 0.40 × C_branch + 0.30 × C_element

| 카테고리 | 사주 점수 안의 비중 | 비교 방식 | 설명 범위 |
|---|---:|---|---|
| 천간·일간 관계 C_stem | 30% | 양쪽 일간을 중심으로 정의한 조합 규칙 | 전통 해석상 관계 특징 |
| 지지 관계 C_branch | 40% | 양쪽 일지·월지·년지를 위치별로 비교 | 닮은 지점·해석상 조율 지점 |
| 오행·용신 관계 C_element | 30% | 같은 기준의 오행과 용신 해석을 양방향으로 비교 | 해석상 보완 관계 |
| 상대 기준 십성 | 별도 0% | A 기준의 B, B 기준의 A를 구분 | 천간 관계를 설명하는 보조 자료 |
| 신강약·격국 | 별도 0% | 용신 관련 규칙의 문맥으로만 사용 | 독립적인 사람 평가 점수가 아님 |
| 신살·대운·세운 | 0% | 기본 순위에서 사용하지 않음 | 별도 선택 콘텐츠로 검토 |

일주 종합 궁합 점수를 추가로 더하지 않는다. 일간·일지·합충·십성에 같은 관계가 반복 반영되는 것을 막기 위해서다.

### 4.2 규칙표의 계약

천간 조합이나 지지 관계에 보편적으로 정해진 연애 점수가 있는 것으로 가정하지 않는다. 아래 함수가 읽는 조합별 규칙표는 제품 정책으로 별도 작성·검토해야 한다.

- lookup_stem_rule(day_stem_A, day_stem_B, context, rule_version)
- lookup_branch_rule(position, branch_A, branch_B, context, rule_version)
- lookup_element_rule(chart_A, chart_B, provider_method, rule_version)

규칙표의 한 행에는 다음을 저장한다.

- rule_id, version
- 적용할 원천 데이터와 조건
- 해당 조건에서 반환할 0~100 점수
- 근거 설명과 참고 자료
- 어떤 항목의 점수에 반영되는지
- 대칭 규칙인지 방향성이 있는 규칙인지
- draft 또는 approved 상태

조합별 원전·해석 검토가 끝나지 않은 규칙은 draft로 유지한다. 실제 사용자 순위에는 approved 규칙만 사용한다. 명세상의 가중치와 뒤의 가상 점수 예시가 조합별 규칙표의 완성을 의미하지는 않는다.

합이 있다고 일괄 가산하거나 충이 있다고 나쁜 사람으로 분류하지 않는다. 규칙이 다룰 수 없는 문맥은 ‘판단 보류’로 남긴다. LLM이 비어 있는 점수를 채우게 하지 않는다.

### 4.3 카테고리별 계산

C_stem:
- 초기에는 일간끼리의 관계만 사용한다.
- 같은 관계에서 파생한 십성을 별도 점수로 추가하지 않는다.
- 방향성이 있는 해석이면 A→B와 B→A를 저장하고 규칙표에서 정한 결합 방식을 사용한다.

C_branch:
- 초기 위치 비중은 일지 60%, 월지 25%, 년지 15%로 둔다.
- 각 위치의 문맥을 포함한 승인 규칙표 값을 합산한다.
- 모든 3×3 교차 지지 조합을 동시에 가산하지 않는다.
- 삼합 등 여러 글자가 필요한 관계는 단순 두 글자 관계와 중복될 수 있으므로 v0에서는 설명 자료로만 보류한다.
- 년지 비중은 대학생의 출생연도 분포와 연관될 수 있으므로 연도별 노출 편중을 점검한다.

C_element:
- A가 B를 해석하는 값 E_A(B), B가 A를 해석하는 값 E_B(A)를 계산한다.
- 초기 결합은 C_element = (E_A(B) + E_B(A)) / 2로 둔다.
- 두 방향의 값은 설명·진단에서 함께 보존한다.
- ‘적은 오행 = 용신’, ‘없는 오행을 채우면 무조건 좋은 궁합’ 규칙은 사용하지 않는다.
- 단순 글자 수 분포와 공급자 가중 분포를 혼용하지 않는다.
- 용신·신강약은 공급자가 채택한 해석 체계와 함께 사용한다.

### 4.4 중복 가산 방지

각 근거를 evidence_id로 식별하고 한 점수군에만 귀속한다. 여러 설명에서 같은 근거를 보여줄 수 있지만 계산에는 한 번만 반영한다.

예: 일간 간 관계가 C_stem에 들어갔다면 동일 관계에서 파생한 상대 십성 설명은 점수 0의 설명 항목으로 남긴다.

공급자 궁합 API의 전체 점수를 사용할 경우에는 자체 S와 비교하는 별도 기준선 모델로 둔다. 두 점수를 중첩하지 않는다.

## 5. 출생시간 미상·누락 처리

v0 추천 순위는 모든 사용자에게 공통 3주인 년·월·일 기준을 적용한다. 두 사람이 생시를 모두 아는 경우 4주 해석은 상세 화면에 별도로 제공한다.

- 3주 순위용 원국과 4주 상세용 원국을 별도 구분한다.
- 3주 순위에 사용하는 오행·용신·강약도 3주 기준으로 계산돼야 한다.
- 알려진 생시를 단순히 화면에서 숨기면서 4주 파생지표를 쓰면 안 된다.
- 임의의 정오·자정을 넣지 않는다.
- 생시 미상에 감점을 주거나 ‘정확도 75%’ 같은 근거 없는 수치를 표시하지 않는다.
- 양력·음력·윤달·출생시간대·시각 보정·날짜 경계 옵션을 통일한다.

HRUM 문서는 생시를 생략했을 때 3주 기준 파생지표를 반환한다고 안내한다. 실제 연동에서는 응답 계약을 검증해야 한다.

필수 원국 누락은 오류 또는 재처리 상태로 둔다. C_element 같은 선택 해석 자료가 일부 후보에서 없으면, 그 후보만 가중치를 재분배하지 않는다. 동일 비교 목록 전체를 사전에 정의한 core 모델로 평가하거나, 해당 후보의 계산을 보완한 후 추천한다.

core 모델 예:
S_core = (0.30 × C_stem + 0.40 × C_branch) / 0.70

S와 S_core 결과를 한 추천 목록에서 같은 척도처럼 섞지 않는다. 사용 모델을 결과에 기록한다.

## 6. 양방향 선호 P

P(A, B) = min(P_A(B), P_B(A))

P_A(B)는 A가 직접 밝힌 선호와 B의 자기 보고 응답을 비교한다. 필수 조건은 후보 필터에서 처리하고 여기서는 선택적 선호만 계산한다.

최소 질문 네 개:
1. 평소 연락 빈도
2. 만나고 싶은 빈도
3. 계획적인 약속과 즉흥적인 약속 중 선호
4. 조용한 활동과 활동적인 경험 중 선호

각 항목을 1~5 척도로 받고 원하는 상대의 허용 범위 [l, u]도 받는다. 범위 안이면 해당 항목 100점, 범위 밖이면 아래처럼 거리로 계산한다.

distance(x, [l, u]) = max(l - x, 0, x - u)
item_fit = 100 × max(0, 1 - distance / 4)

P_A(B)는 네 항목의 평균이다. B→A도 같은 방식으로 계산한다. 한쪽만 높은 선호를 평균으로 감추지 않도록 최솟값을 사용한다.

누락 답변을 낮은 선호로 간주하지 않는다. 최소 질문 완료를 받은 뒤 해당 모델로 평가한다.

사주에서 유래한 ‘적극적’, ‘배려형’ 등의 태그를 자기 보고 응답에 다시 넣지 않는다. 이는 사주 근거의 중복 가산이 된다.

## 7. 만남 가능성 M과 활동 추천

M = 0.50 × 시간점수 + 0.30 × 이동점수 + 0.20 × 활동선택점수

다음 숫자는 운영 테스트용 초기 정책이다.

| 항목 | v0 점수 |
|---|---|
| 향후 14일에 두 사람 모두 가능한 60분 이상 시간대 | 서로 다른 날짜 3개 이상 100, 2개 75, 1개 50, 없음은 약속 제안 불가 |
| 후보 장소까지 양쪽의 예상 이동 부담 | 허용 시간 대비 부담비율이 둘 다 50% 이하 100, 둘 다 75% 이하 70, 둘 다 100% 이하 40, 초과는 해당 장소 제외 |
| 시간·예산·취향 조건을 만족하는 서로 다른 활동 | 3개 이상 100, 2개 75, 1개 50, 없음은 약속 제안 불가 |

먼저 시간·장소·활동·예산 조건을 동시에 충족하는 계획 객체의 집합을 만든다. 계획 하나에는 날짜·시간·장소·활동·양쪽 비용·이동시간이 모두 들어 있어야 한다. 시간점수의 날짜 수와 활동선택점수의 활동 수는 이 공동 실행 가능 집합에서만 센다. 이동점수는 이 집합의 계획 중 가장 부담이 적은 계획을 기준으로 계산하고 그 계획을 함께 제시한다. M은 단일 예약의 품질만이 아니라 두 사람이 고를 수 있는 계획 집합의 유연성을 나타낸다.

활동 필수 필터:
- 양쪽 모두 가능한 시간과 이동 범위
- 매칭비를 포함한 양쪽 개인별 총예산
- 양쪽이 피하고 싶은 활동 제외
- 운영 시간, 소요 시간, 동반 인원, 취소 조건 확인
- 예약 가능 여부가 확인되지 않았다면 ‘예약 가능 미확인’ 표시. 확정 예약처럼 안내하지 않음

활동 순위 초안:
ActivityScore = 0.45 × 양방향 활동선호 + 0.30 × 이동·예산 적합도 + 0.15 × 시간 적합도 + 0.10 × 양쪽이 확인한 사주 테마 선호

사주 해석에서 ‘새 경험’, ‘차분한 대화’ 등의 테마를 제안할 수 있다. 다만 ‘이 테마에 공감하나요?’에 두 사람이 답한 뒤 선호로 사용한다. 확인하지 않은 사주 테마만으로 비싼 활동이나 특정 장소를 강제하지 않는다.

테마 확인 전에는 모든 후보 활동에 동일하게 45:30:15를 정규화한 기본 모델을 사용한다. 일부 활동에만 임의로 10점을 보태지 않는다.

활동 태그의 출처:
- saju_interpretation: 사주 해석에서 제안
- user_confirmed: 사용자가 공감하거나 직접 선택
- observed_behavior: 실제 예약·평가로 확인

수익용 제휴 수수료율은 ActivityScore에 넣지 않는다. 협찬 노출은 적합도 순위와 구분한다.

## 8. 가상 계산 예시

아래는 실제 사주를 계산한 값이 아니라 최종 순위 산식을 확인하기 위한 가상 입력이다. 세 후보 모두 필수 조건과 데이터 검증을 통과했다고 가정한다.

| 후보 | 천간 | 지지 | 오행·용신 | S | A→후보 | 후보→A | P | M | R |
|---|---:|---:|---:|---:|---:|---:|---:|---:|---:|
| B | 80 | 85 | 80 | 82 | 87.5 | 75 | 75 | 81 | 80.10 |
| C | 90 | 90 | 90 | 90 | 56.25 | 87.5 | 56.25 | 56 | 76.46 |
| D | 70 | 70 | 70 | 70 | 100 | 100 | 100 | 100 | 82.00 |

순위는 D → B → C이다. 사주 비중이 가장 크지만 상호 선호와 실제 만남 조건도 순위를 바꿀 수 있다. D가 더 좋은 사람이라는 뜻은 아니다.

선호 점수 예: 87.5는 [100, 100, 75, 75], 75는 [75, 75, 75, 75], 56.25는 [75, 50, 50, 50]의 평균이다. M=81은 시간 100·이동 70·활동 50, M=56은 시간 50·이동 70·활동 50을 적용한 값이다.

숫자 예시는 별도로 산술 검산했다. 실제 사주 규칙표나 사용자 효과를 검증한 결과는 아니다.

## 9. 추천 결과 계약과 의사코드

각 결과에는 다음 값을 포함한다.

candidate_id
ranking_score
saju_score
preference_score
meeting_score
model_id
rule_version
chart_basis
reasons[]
limitations[]
suggested_plans[]
computed_at

reasons의 각 항목:
- source: saju_rule / user_report / availability
- evidence_id
- component
- message_template_key
- verified_values

의사코드:

```text
A = load_verified_profile(user_id)
candidates = find_mutually_eligible_candidates(A)

comparable = prepare_common_three_pillar_basis(A, candidates)
model = choose_one_model_for_entire_candidate_list(comparable)
ranked_results = []
pending_results = []

for B in comparable:
    evidence = extract_cross_chart_features(A, B)
    ensure_no_duplicate_evidence(evidence)

    saju_result = evaluate_approved_saju_policy(evidence, model)
    if saju_result.status != "complete":
        pending_results.append(B, "rule_review_or_recalculation")
        continue
    S = saju_result.score

    P_ab = preference_fit(A.wanted_ranges, B.self_report)
    P_ba = preference_fit(B.wanted_ranges, A.self_report)
    P = min(P_ab, P_ba)

    plans = find_jointly_feasible_plans(A, B)
    if plans is empty:
        if mode == "browse":
            pending_results.append(B, "schedule_unconfirmed")
        continue

    M = score_feasible_plan_set(plans)
    R = 0.60*S + 0.25*P + 0.15*M

    ranked_results.append(B, R, S, P, M, evidence, plans, versions, limitations)

rank ranked_results by R
apply capacity limits and repeat-exposure limits
return top 5 with grounded explanations and separately labelled pending_results
```

초기 노출 정책:
- 하루 추천 5명은 테스트용 정책이며 변경 가능.
- 동시에 진행 중인 소개 수에 상한을 둔다.
- 이미 거절한 동일 쌍은 일정 기간 다시 보여주지 않는다.
- 1점 미만의 작은 점수 차이를 절대 우열로 표현하지 않는다.
- 동점 후보는 최근 노출이 적은 후보 우선, 마지막 동률은 날짜·사용자 ID 기반의 재현 가능한 순서로 처리한다.
- 단일 사용자에게 인기 후보가 집중돼 예약이 불가능해지는 문제를 기록한다.

AI 설명기는 계산 이후에만 실행한다. 점수 변경, 없는 근거 추가, 성격·안전·성적 행동·성공률 단정을 금지한다. 설명에는 실제 사용한 근거와 평가 범위만 포함한다.

## 10. 검증 계획

### 계산 검증

- 동일 입력·옵션·규칙 버전의 동일 결과
- 대칭 규칙에서 A/B 순서를 바꿔도 동일한 결과
- 방향 규칙은 양방향 값을 보존
- birth time 없음 처리와 파생지표 계산 기준 확인
- 필드 누락·알 수 없는 코드·스키마 변경 시 조용히 0점으로 처리하지 않음
- 동일 evidence가 두 번 가산되지 않음
- 점수 근거와 사용자 설명 일치
- 양쪽 선호·예산·시간·차단 조건 위반 후보가 노출되지 않음

### 서비스 지표

| 지표 | 분모 |
|---|---|
| 쌍방 수락률 | 사전에 정의한 유효 추천쌍 |
| 일정 확정률 | 쌍방 수락쌍 |
| 실제 참석률 | 일정 확정쌍 |
| 다시 만나고 싶은 비율 | 참석 후 양쪽 응답을 확보한 쌍 |
| 활동 예약률 | 일정 확정쌍 |
| 추천→참석 전환율 | 최초 유효 추천쌍 |
| 차단·신고율 | 추천쌍 또는 노출 사용자, 실험 내 고정 |

유효 추천쌍의 정의, 응답 관찰 기간, 미열람과 거절의 구분을 사전에 고정한다. 후기 응답률을 함께 보고 응답자만의 만족도를 전체로 일반화하지 않는다.

비교 모델:
- A: S 60%, P 25%, M 15%
- B: S 0%, P 62.5%, M 37.5%
- 가격·설명량·혜택·노출 수는 동일하게 유지한다.

작은 매칭 풀에서 사용자 단위 A/B는 상대방 가용성을 통해 서로 영향을 줄 수 있다. 초기에는 탐색 결과로 해석하고, 이후 독립된 모집 회차나 생활권으로 검증한다. 실험 기간에는 규칙 버전을 고정한다.

확정한 초안:

- 가상 예시 산술 검산

실사용 전 필요한 작업:
1. 공급자와 계산 설정 확정, 상용 가공·저장 조건 확인
2. 천간·지지·오행 문맥별 규칙표 작성과 명리 검토
3. 실제 API 응답 어댑터와 검증 구현
4. 동의·인증·차단·삭제 및 예약 처리 구현
5. 실제 사용자 데이터로 점수 분포·수락·참석·만족 검증

이 문서의 세부 점수군을 실제 소통능력·책임감·정직함 같은 인성 측정값으로 바꾸지 않는다. 추천의 목적은 사람의 가치를 평가하는 것이 아니라, 정해진 해석 기준과 이용자 조건 안에서 소개 후보와 약속을 정리하는 것이다.
