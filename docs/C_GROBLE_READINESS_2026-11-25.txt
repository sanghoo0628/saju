  updated_at 타입/NULL/default와 트리거 활성화, 인덱스 존재, 역할 및 필요 서버 권한.

  Groble 상품/키/서명/HTTP 경로/배포 응답 시간/결제 활성화/환불 정책 완료를 뜻하지 않음.
- 미연결/검토 필요 이벤트가 있으면 attentionRequired=true. 자동 재처리/삭제/환불하지 않음.
- 인덱스 존재와 필수 컬럼을 확인하는 운영 점검이며 모든 SQL 제약/함수/운영 설정의 완전한 감사는 아님.

안전한 실행
1. Node24.22.1 / pnpm11.25.0 및 기존 .env.local 설정 사용.
2. .env.local의 DATABASE_URL, DATABASE_SSL_CA_PATH 또는 DATABASE_SSL_CA_PEM 필요.
   새로운 키를 생성하지 않으며 Groble/HRUM/Supabase 관리자 API 키는 사용하지 않음.
3. 명시적으로 대상 프로젝트 확인 후:
   C_GROBLE_READONLY_PROJECT_REF=<Supabase프로젝트ref> pnpm verify:groble:readonly
4. URL의 프로젝트/사용자/호스트가 맞지 않거나 query/hash가 있으면 접속 전에 거부.
   pg는 URL query로 host/user/ssl을 덮어쓸 수 있으므로 query 없는 URL을 사용.
5. TLS 검증 유지. 자체 CA 파일/PEM은 기존 paymentChatTls 검증기를 사용.
6. 1회 연결은 검사 뒤 폐기. 마이그레이션/테스트 주문/메시지/권한을 생성하지 않음.
7. 종료 코드0=점검한 DB 구조·권한 준비, 2=준비 미완료, 1=설정/접속/쿼리 실패.
   0이어도 attentionRequired 및 paymentActivationChecked:false를 함께 읽을 것.
8. 오류는 제한된 진단 코드와 점검 단계만 출력. 원문 오류/연결 문자열 로깅 금지.
