- 기존 서명/키 교체/원문 검증/완료→서비스 회귀 테스트 유지.
- 새 테스트는 취소·전액/부분 환불, 참조값 누락, 시각 형식, 중복 식별, 개인정보 제외와
  순서에 무관한 파싱을 검증함. 중복 환불 DB 처리 또는 역순 DB 상태 복구를 검증한 것은 아님.

아직 연결하지 않은 것
- 런타임은 unavailablePaymentGateway 유지. PAYMENTS_ENABLED=false 유지.
- DB 이벤트 원장/고유 제약/트랜잭션 내 주문 반영은 다음 단계. 새 마이그레이션 없음.
- 서명 유효성만으로 결제 권한을 주거나 환불 완료로 바꾸지 않음.
- 취소 요청은 환불 완료와 다르므로 곧바로 권한 회수하지 않음.
- 실제 환불 처리, 기존 채팅방 유지 정책, 부분 환불 정책은 팀 합의 필요.
- merchantUid 원 거래를 찾지 못하는 역순 환불 이벤트는 영속 보관/재처리가 필요함.
- 서명 대상이 아닌 전송 멱등 키 하나만으로 중복 처리 완료를 판단하지 않도록
  이벤트 ID 및 환불 거래/시각 키와 함께 DB에서 충돌을 검사해야 함.
- DB 저장/큐 적재 및 원자적 처리 완료 전 2xx를 반환해서는 안 됨.
