C 결제·채팅 화면 오류 복구 보완
2026-11-17 / codex/c-payment-chat

변경한 동작
1. 대화 목록 로딩·실패·빈 목록을 구분한다. 실패 안내와 목록 재시도 버튼을 유지한다.
   목록 요청은 새 조회/화면 해제 시 중단하고, 로그인/권한 실패 시 이전 목록을 지운다.
2. 결제 확인 지연의 '같은 주문 다시 확인'은 주문 상태 GET만 수행한다.
   지연된 데모 결제 완료는 별도 버튼이며 재확인으로 결제를 완료시키지 않는다.
3. 주문 준비/주문 확인 오류에서 적절한 재시도 버튼을 제공한다.
   주문 ID가 있으면 새 주문을 만들지 않고 같은 주문을 조회한다.
4. 결제 모달 안에 요청 실패 안내와 주문 번호를 표시한다.
   프로필/결제 창이 바뀐 뒤 도착한 이전 작업의 오류는 새 창에 표시하지 않는다.
5. 환불 대기는 환불 완료와 구분하고, 취소/환불 상태에서는 대화 요청 버튼을 표시하지 않는다.
   데모 시나리오에 환불 대기와 결제 취소를 추가했다.
6. 메시지 조회 오류와 전송 오류를 별도 상태로 관리한다.
   자동 조회 성공이 전송 실패 안내를 지우지 않으며, 초안도 유지한다.
   응답이 유실됐을 때 자동 재전송하지 않고 기록 확인 버튼을 제공한다.
7. 기록 로딩/조회 실패 중에는 입력·전송을 비활성화한다.
   401/403/404 접근 실패는 기록을 지우고 입력·답장 체험을 막으며 해당 방의 자동 조회를 중단한다.
   늦게 도착한 조회나 답장 응답도 접근 거부 뒤에 기록을 복원하지 못한다.
8. 데모 답장 버튼의 중복 클릭을 막고, 로딩 영역에 aria-busy를 표시한다.

브라우저에서 확인한 흐름 (로컬 가상 데이터)
- 목록 API 503: 빈 목록 대신 오류 표시 → 재시도 후 받은 요청 복구.
- 결제 지연: 동일 주문 번호 유지 → 재확인은 GET만 실행 → 별도 데모 완료 후 요청 가능.
- 결제 확인 → 대화 요청 → 상대 수락 체험 → 채팅 화면 연결.
- 메시지를 서버에 저장한 뒤 응답만 503으로 교체: 초안/안내 유지, 기록 조회로 전달된 메시지 확인.
  프록시 기록에서 메시지 POST는 한 번뿐이며 자동 재전송하지 않았다.
- 기록 조회 503: 조회 오류와 비활성 입력 표시 → 오류 해제 후 자동 조회로 기록/입력 복구.
- 기록 조회 403: 이전 메시지를 지우고 입력과 답장 체험 비활성화.
- 환불 대기: 환불이 아직 완료되지 않았다는 안내, 대화 요청 버튼 없음.
- 취소: 취소된 주문 안내, 대화 요청 버튼 없음.
- 마지막 정상 화면 확인 시 브라우저 오류 로그 없음. 의도한 503/403은 테스트 실패 주입이다.

테스트 환경
기존 4173 서버가 이전 코드를 캐시하고 있어 해당 프로세스는 종료하지 않았다.
검증용 Vite를 별도 포트 4175에서 실행하고, 임시 프록시 4174를 통해 오류를 주입했다.
프록시는 저장소 밖 work/의 검증 도구이며 앱/배포 코드에 포함하지 않는다.
데모 서버의 기존 고정 Origin(4173)에 맞춰 프록시가 Origin을 변환했다.
일반 사용 시 기본 포트 4173으로 npm run demo:dev를 실행한다.
변경 전부터 실행 중인 서버는 종료 후 다시 실행해야 최신 서버 코드를 읽을 수 있다.

A가 화면을 가져갈 때 추가로 연결할 props
- PaymentDialog: actionError, onRetry, onFinishDelayedDemo 추가.
  onFinishDelayedDemo 및 시나리오 버튼은 로컬 체험 전용이므로 운영 앱에서는 제거한다.
  onRecheck는 실제 주문 상태 조회에만 연결한다.
- ChatPanel: listLoading, listError, onReload 추가.
- App.tsx, catalog.ts, demo/server.ts는 가상 데이터 조합 예시다.
  공통 앱에서는 실제 로그인 사용자와 프로필 데이터를 전달해야 한다.
- 실제 결제 완료/취소/환불은 검증된 서버 주문 상태를 사용한다.
  데모의 취소 상태 변경이나 가상 상대 비활성화 코드를 운영에 가져가지 않는다.
