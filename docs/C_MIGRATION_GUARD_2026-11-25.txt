마이그레이션 파일 검사 — 2026-11-25

문제
- 서로 다른 이름의 SQL이 같은 버전을 사용해도 기존 PGlite/native harness는 두 파일을 순서대로 실행해 테스트가 통과할 수 있었다.
- 실제 적용 이력을 사용하는 Supabase 배포에서는 이 결과만으로 버전 충돌이 해결되지 않는다.

실행
- pnpm verify:migrations
- supabase/migrations 바로 아래의 SQL 파일 이름을 읽는다. DB·환경 변수·SQL 본문은 읽지 않는다.
- 정상은 종료코드0, 버전 중복/잘못된 파일명/SQL 경로가 일반 파일이 아님/빈 디렉터리/읽기 실패는1.
- 파일명은 14자리 버전_설명.sql. 버전이 같으면 설명이 달라도 충돌이다. 번호가 연속일 필요는 없다.
- README·백업 파일은 무시한다. SQL로 위장한 디렉터리/심볼릭 링크는 거부한다.

연결
- pnpm check의 첫 검사.
- pnpm verify:integration --run의 첫 단계(migrations). 실패하면 나머지 앱/DB 단계는 실행하지 않는다.
- CI app/postgres 두 job에서 의존성 설치 직후 실행한다. 자동 배포·마이그레이션 적용 단계는 추가하지 않았다.

검증
- 실제 A/C의001 충돌과 B/C의002 충돌을 회귀 테스트로 포함한다.
- 정상/잘못된 이름/읽기 실패/실제 임시 파일 충돌/SQL 디렉터리·심볼릭 링크/검증 중단 동작을 검사한다.
- 검사 도구 테스트 총22개, lint/typecheck 로컬 통과. 전체 앱/DB 검증은 해당 코드 커밋의 CI 결과를 확인한다.

한계
- SQL 내용의 정합성, 적용된 파일 불변 여부, remote 적용 이력, RLS, 실제 기능 흐름은 판정하지 않는다.
- 개별 PR에서는 통과해도 두 브랜치를 합칠 때 충돌할 수 있으므로 최종 통합 트리에서도 실행한다.
- pnpm test만 단독 실행하면 파일 검사는 포함되지 않는다. pnpm check, verify:integration 또는 CI로 확인한다.
