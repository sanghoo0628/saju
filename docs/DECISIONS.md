## 개발 기본안

- 공통 타입의 상품 상수는 `src/contracts/product.ts`에 둔다. API의 대상 필드·상태 이름은 C 코드가 제공되면 맞춘다. 이 타입만으로 결제 또는 접근권한이 구현된 것은 아니다.
- 공개 DTO는 필요한 카드 필드만 명시적으로 투영한다. 무료 열람으로 바뀌어도 학교 이메일·출생정보·사주 원문·비공개 사진 경로를 전체 공개하지 않는다.
- 실제 Supabase 인증만 서버 사용자 ID로 인정한다. 화면용 사주 mock은 로그인이나 결제 성공을 위조하지 않는다.
- 학교 도메인은 설정으로 받는다. 빈 허용 목록을 전체 허용으로 취급하지 않는다. 학교 이메일 확인은 재학 신분의 완전한 보증으로 표시하지 않는다.
- 사주 공급자는 HRUM을 개발 기본안으로 선택했다. 공식 문서와 가상 입력의 guest 3주/4주 응답을 확인하고 실제 partner 어댑터·용신/강약 정규화·B용 3주 입력을 구현했다. partner 키 인증·로그인 후 실제 호출은 외부 설정 대기다. 미설정/실패를 mock 성공으로 바꾸지 않는다. 근거와 대안은 [SAJU_PROVIDER_COMPARISON.md](SAJU_PROVIDER_COMPARISON.md)에 있다.
- `legacy_demo_v1`은 오락용 숫자 전략이고 `saju_hybrid_v0_1`과 별개다. 규칙 승인·필수 입력이 없으면 hybrid는 `not_ready`. A는 B 소유 추천 점수나 승인 규칙을 만들지 않는다.
- 원격 대상은 sanghoo0628/saju로 확인했다. 재설계 작업에서는 로컬 A 준비 변경만 적용하며, 실제 통합은 최신 C 이력을 보존한다. 다른 프로젝트 저장소·Supabase DB를 선택하지 않고, 실서비스 배포·운영 DB 변경·실결제를 실행하지 않는다.
